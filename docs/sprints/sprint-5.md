## Sprint decisions

- **The distribution is `fastapi-sentinel` (SEN-36, ADR-0008's fallback):** PyPI refused a pending publisher for `sentinelapi` as too similar to the existing `sentinel-api`, which the check of SEN-36 missed because it looked up the exact name only. The package stays `import sentinelapi`. The tag `v1.0.0`, which had published nothing to PyPI, moved to the commit with the new name.
- **Comments only for what the code cannot say (product owner, 2026-10-22):** the rule is in SPEC › Engineering rules. Applied to the whole repository in #33: story numbers, audit-probe history and "used to" docstrings left the code, as did comments that repeated it and section banners; one test comment contradicted its test. Python went from 302 comments and docstrings to 273.
- **The demo has a server of its own (SEN-33, ADR-0009 option 3):** an `e2-small` VM on Google Cloud's free trial, like Willay's and VeriLedger's, rather than sharing theirs. `sentinelapi.duckdns.org` was taken, so the demo is `sentinelaapi.duckdns.org`. The deploy is run over SSH with a key used for nothing else.
- **Refused attempts count against a locked account (SEN-43).** CRITICAL means an attack that goes on after the lock; counting only failures, it could never come with `lock`, the default. Each attempt counts once: in `check` when the account is locked, otherwise in `record_failure`.
- **Alerts are held back per account when the event has one (SEN-43),** per source otherwise: credential stuffing comes from a new address every time, and one message per address is a flood.
- **AR-19: the README's guarantees name tests that exist (SEN-37).** A guarantee linked to a test that was later renamed would be a claim nobody checks.
- **The README's known limitations are the design's trade-offs (SEN-37),** each with its ADR, plus password spraying, which neither axis catches, instead of "none known".
- **PyPI's description gets absolute links (SEN-37)** through hatch-fancy-pypi-readme, a build-time plugin only: relative links work on GitHub and lead nowhere on PyPI.

## Retro

- **Went well:** checking every claim against the code before 1.0.0 paid off twice: it found that credential stuffing never reached CRITICAL (SEN-43), and it made the README's guarantees a test (AR-19). The deploy followed the runbook as written, and each step was checked from outside: `verify.sh`, the three attacks through the public console, `pip install` from PyPI.
- **To improve:** the name check of SEN-36 looked up the exact name only, while PyPI also refuses names that differ by separators or confusable characters; it cost a rename and a moved tag. And the release PR said "on PyPI" before anything was published, which was true only once the publishers matched.
- **To try:** check a name in PyPI's folded form before choosing it, and set the trusted publishers up, on both indexes, before the release PR. Watch the public demo with a scheduled check, and decide where it runs before Google Cloud's free trial ends in January 2027.
